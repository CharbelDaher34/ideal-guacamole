How it is stored

folder daily_flows

Clients split into groups, files split by month

400,000clients
÷ 5,000clients per group
80groups
≈ 2,000files (80 × 25 months)

The group of a client is fixed: a hash of its client number (CRC32) modulo 80. The same client is always in the same group, so its rows are always in the same files.

Each night, only the new days

staging, every night

Already stored up to 9 Nov. Tonight's cut-off is yesterday, 10 Nov.

Already in daily_flowsRead tonight: only the days after the last stored day, up to yesterday

What happens to the files

  1. The query reads only 10 Nov (a date filter on the value date).
  2. For each group, its Nov file is read, the new day is added, and the result is written as a new file. The files of older months are not touched.
  3. The manifest switches to the new files, only after every file is written.
  4. The old Nov files are then deleted.

Special cases

  1. First run or Full rebuild: the whole history is read (the setting history_months), and every file is written from nothing.
  2. Nothing new: daily_flows is not touched.
  3. A failed night: the manifest still points to the old files, so the data stays as it was. The next night reads the same days again.
  4. A new month starts: each group gets a new month file.
4

Nightly forecast: workers take one group each

recipe nightly_forecast

80 groups, 4 workers: each worker takes the next waiting group

Workers are threads (setting inference_workers). Each holds one group in memory, so memory grows with the number of workers. In the load test, 4 workers was the fastest on the shared server.

What one worker does with one group (about 5,000 clients)

1 · 9% of the time

Read

Only its group's last 13 month files, straight from disk. Keeps the last 365 days.

Polars read_parquet
2 · 44%

Prepare

Drops clients with too little history. Builds 3 rows per client and category (one per window), with day_365 … day_1.

3 · 39%

Model

Gives P10, EV and P90 for every row. Uses its share of the CPU cores.

CatBoost
4 · 6%

Format

One wide row per client, with a status: OK, NOT_ENOUGH_HISTORY or NO_POSTINGS.

5 · 1%

Write

One file, part_00007.parquet. One worker writes at a time.

Shares measured in the load test: 400,000 clients, 4 workers, about 56 seconds of forecasting.
