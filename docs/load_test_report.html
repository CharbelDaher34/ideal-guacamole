How to run the nightly forecast for 400,000 clients

The nightly forecast was timed on fake data the size of the bank's (400,000 clients, 24 months of history) with 6 setups: pandas or Polars, and 2,000, 5,000 or 20,000 clients per chunk.

Why

  • Bigger chunks are slower. Preparing a chunk (one table per client and category, one column per 30-day period) takes longer than in proportion to its size, so many small chunks beat a few big ones. At 20,000 per chunk preparing took 308 s with pandas against 121 s at 5,000, and memory rose from 3.4 to 8.3 GB.
  • The engine matters little with small chunks. Polars only speeds up preparing (−15% at 2,000 to 5,000 per chunk, −42% at 20,000). Reading, the model and formatting are the same code for both.
  • The model is not the bottleneck. Real CatBoost (3 models: P10, EV, P90) takes 5–9 s for 400,000 clients. A heavier model would add to that, not change the other steps.
  • It grows in a straight line. In earlier runs (without a model), 800,000 clients took about twice as long as 400,000, with the same memory: memory depends on the chunk size, not on the number of clients.

How it was measured

  • Scenario Load test (zone Load test, apart from the real data), on the local sandbox: Dataiku 14.2 Free Edition, 48 cores, 125 GB of memory, shared with other projects.
  • Fake data: 400,000 clients, 24 months, about 40 postings a month each: 332 million daily rows, 3.2 GB of Parquet. 10% of clients have a shorter history, so 19,244 get NOT_ENOUGH_HISTORY.
  • Model: real CatBoost with quantile_boosting's inputs, trained on 2 clients only, so its forecasts mean nothing and its prediction time is real.
  • Not included: the warehouse read (staging) and training. Run the same scenario on the bank's server before relying on these numbers there.
